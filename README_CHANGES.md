# 온기 (we-meet) 변경 사항: MVP 이후

MVP 커밋 `8ce565b`(2026-10-22) 이후 바꾼 내용을 정리한 문서다. 실행 방법과 전체 구조는 [README.md](README.md)에 있다.
아래 내용은 모두 `main`에 들어가 있다 (2026-10-27 기준).

## 한눈에 보기

- 대본을 하나만 만들던 것을 **분위기가 다른 후보 3개**로 만들고 자녀가 고르게 바꿨다.
- **말투(반말/존댓말)** 를 코드로 먼저 정해서 후보 3개가 같은 말투를 쓴다. 부모님 정보에서 고를 수 있다.
- 부모님이 부르는 **자녀 이름**을 따로 받는다. 대본과 시청 페이지에 카카오 닉네임 대신 쓴다.
- AI가 메모에 없는 날씨·요일·시각을 지어내거나 메모의 날짜·시각을 빼거나 바꾸면 **코드로 잡아서** 다시 쓰게 하고, 남으면 화면에 경고한다.
- **보이스피싱 금칙어**를 넓혔다. 금액만 대는 송금 요청, 주소 누르기, 어플 설치도 막는다.
- 대본 생성에 **15초 시간 한도**를 두었다.
- 대화방이 생긴 뒤로, 직전 편지에 부모님이 남긴 **답글에 대본이 반응**하도록 최근 대화를 함께 넣는다.

## 1. 대본 후보 3개

메모 하나로 후보 3개를 동시에 만든다. 자녀가 고른 분위기(`chosen_style`)와 직접 고쳤는지(`script_source`)가 남아서 나중에 선호 데이터로 쓸 수 있다.

| 분위기 | 목표 (공백 제외) | 무엇을 쓰는지 |
|---|---|---|
| 담백하게 | 15~45자 | 메모 내용만. 인사·걱정·애정 표현 없음 |
| 다정하게 | 60~85자 | 메모 + 안부 질문 하나 + 당부 하나 + 마음 표현 |
| 밝게 | 45~65자 | 반가운 호칭, 짧은 문장, 느낌표, 기대감과 응원 |

- 분위기는 형용사가 아니라 "무엇을 덧붙이는지 + 문장 모양 + 짧은 예시"로 정의했다. 형용사만 주면 후보끼리 비슷해졌다 (후보 간 겹침 0.29 → 0.17).
- **담백하게 최소 분량을 30자에서 15자로 낮췄다**: "메모 내용만" 쓰는 분위기라 "주말에 갈게" 같은 짧은 메모로는 30자를 채울 수 없었다. 시도 70번 중 32번이 짧다고 다시 쓰였고, 늘리라는 피드백이 메모에 없는 말을 지어내게 했다. 짧은 메모면 영상이 3초 남짓으로 짧아진다.
- **모양 예시를 목표 분량에 맞췄다**: 예전 예시는 모두 목표보다 짧았다 (다정하게 35~41자, 밝게 40~42자). 지금은 다정하게 63~68자, 밝게 46~48자다.
- 같은 문장이 나오면 하나로 합친다. AI 연결이 안 돼서 기본 대본 하나만 남으면 고르는 단계 없이 바로 쓴다.
- 후보 화면에서 "존댓말로 바꾸기"나 "새로 써 주세요"를 누르면 후보 3개를 다시 만든다.

## 2. 말투 (반말/존댓말)

후보를 따로 요청하기 때문에 프롬프트로 "말투를 통일하라"고 해도 섞였다. 그래서 코드로 먼저 정하고, 세 요청에 똑같이 넣는다.

우선순위: 이 메시지에서 바꾼 값 > 이 메시지에 쓰던 값 > 부모님 정보에서 고른 말투 > 자주 보내는 메시지 > 메모 어미

- 메모는 앱에 쓰는 글이라 부모님께 존댓말을 쓰는 사람도 반말로 쓰기 쉽다. 그래서 메모 어미는 가장 마지막에 본다.
- 부모님 정보 화면에서 할머니·할아버지를 고르면 존댓말이 미리 골라진다. 엄마·아빠는 사람마다 달라서 비워 둔다.
- 생성된 대본에 다른 말투 문장이 섞이면 다시 쓰게 한다.

## 3. 자녀 이름

`parent_profiles.child_call_name`에 부모님이 자녀를 부르는 이름(예: 준하, 막내)을 받는다. 처음에는 가입 이름으로 채워 두고 확인받는다.
대본 프롬프트와 시청 페이지(`/api/watch`)의 `child_name`이 이 값을 쓴다. 비어 있으면 가입 이름을 쓴다.

## 4. 사실 검사

프롬프트로 금지해도 AI가 날씨·요일·시각을 지어냈다 (테스트에서 6/6). 그래서 메모와 대본을 코드로 대조한다.

| 검사 | 잡는 것 | 예 |
|---|---|---|
| 지어냄 (`unsupported_facts`) | 메모에 없는 날씨, 요일, 시각 | 메모에 날씨 얘기가 없는데 "날이 춥네요" |
| 빠짐·바뀜 (`missing_facts`) | 메모에 있던 요일, 시각이 빠지거나 바뀜 | "목요일" → "오늘" |
| 〃 | 메모에 있던 날짜, 분, '반', 오전/오후가 빠지거나 바뀜 | 11월 3일 → 5일, 오후 → 오전, 3시 30분 → 세 시 |

- 걸리면 무엇이 틀렸는지 알려 주고 다시 쓰게 한다. 3번 다 걸리면 문제가 가장 적은 대본을 쓴다. 사실 오류는 길이·말투 문제보다 무겁게 친다.
- 남은 문제는 후보 카드와 대본 아래에 노란 경고로 보여 준다. 영상 만들기는 막지 않는다. 자녀가 직접 고친 대본에는 경고하지 않는다.
- 시각을 찾을 때 앞 단어 끝 글자를 숫자로 읽지 않는다. "언니네 시댁"을 4시로, "모두 시원"을 2시로 읽던 문제를 고쳤다. "오후세시", "내일3시"처럼 붙여 쓴 시각은 읽는다. "15시"는 3시로 읽는다.
- 날짜와 분은 메모에서는 숫자로 적힌 것만 읽고, 대본에서는 한글 숫자(삼 일, 삼십 분)까지 읽는다. 그래서 "이 일 끝나면"을 2일로 읽지 않는다.
- 날짜가 아닌 표현은 날짜로 보지 않는다: "1일 3회", "3일 동안", "3일 뒤".
- 오전/오후는 시각 바로 앞에 붙은 말만 본다. "아침 꼭 챙겨 드세요"의 아침은 끼니라서 무시한다. 오후와 저녁처럼 같은 쪽이면 바뀐 것으로 보지 않는다.
- 날씨는 "더우니까", "추우니까", "더위", "추위"도 날씨로 읽는다. 예전에는 메모의 "더우니까"를 못 읽어서, 대본의 "더운데"를 지어낸 날씨로 잘못 잡았다.

## 5. 금칙어 (보이스피싱 방지)

자녀 목소리로 돈이나 개인정보를 요구하는 영상은 만들지 않는다. 대본에 아래 내용이 있으면 영상 만들기가 막힌다.

- **새로 막는 것**
  - 금액만 대는 요청: "십만 원만 보내 주세요", "삼십만 원이 필요해요"
  - 사이에 말이 끼는 요청: "용돈 좀 미리 보내줄 수 있어?", "병원비 급한데 좀 보태줘"
  - 돈을 뜻하는 다른 말: "급전이 필요해", "생활비 좀 부탁할게"
  - '주다'로 하는 요청: "돈 좀 줘", "오십만 원만 주실 수 있어요?"
  - 그 밖에: "문자로 보낸 주소 눌러 주세요", "링크 들어가서", "어플 하나 깔아"
- **통과하는 것**
  - 이미 받은 돈에 대한 인사: "용돈 줘서 고마워", "용돈 보내줘서 고마워", "보내 주신 거 받았어"
  - 돈 요청이 아닌 말: "돈 걱정 말고 반찬 보내 줘서 고마워", "오만 원짜리 케이크 보내 드릴게요", "돈 필요 없으니까", "십만 원어치 장 봤어요"
- **기준**: 돈을 뜻하는 말과 요청 동사 사이에는 조사와 "미리, 급하게, 급한데, 그런데" 같은 말만 허용한다. 그래서 "돈 걱정 말고 반찬 보내" 같은 문장은 통과한다. 이 목록은 실제 실험에서 AI가 쓴 표현을 기준으로 만들었다.
- 금칙어가 들어간 후보는 후보 카드에 빨간 글씨로 이유를 보여 준다. 고를 수는 있지만 고친 뒤에야 영상을 만들 수 있다.
- 메모 단계에서는 막지 않는다. AI가 대본에서 빼거나, 남으면 위처럼 표시된다.
- 아직 못 잡는 표현이 있다 (알려진 한계 참고).

## 6. 생성 과정

```
말투 결정 → 분위기 3개 동시 요청 ─┬─ HyperCLOVA X 호출 (연결 끊김·429·5xx면 2초/4초 쉬고 재시도)
                                  ├─ JSON 꺼내기 → 금칙어·길이·사실·말투 검사
                                  ├─ 문제 있으면 이유를 붙여 다시 쓰기 (최대 3번)
                                  └─ 15초가 지나면 멈추고, 가장 나은 대본 또는 기본 대본
```

- **시간 한도 15초** (`TIME_LIMIT_SECONDS`): 대본 생성은 "메시지 만들기" 요청 안에서 돈다. 오래 걸리면 프록시나 브라우저가 먼저 끊고, 그사이 서버는 메시지를 저장해서 다시 누르면 중복이 생긴다. 예전에는 API가 멈추면 한 분위기당 1~2분 넘게 걸릴 수 있었다.
- **`maxTokens` 300 → 200**: 호출 한도는 입력 토큰에 `maxTokens`를 더해서 센다. 실제 출력은 최대 81토큰이었다 (3차 실험).
- **프롬프트에서 오늘 날짜를 뺐다**: 넣었더니 메모의 "목요일"을 "오늘"로 바꿨다 (6/6).
- **상황 템플릿 설명**: "날씨를 챙겨 드린다"처럼 쓰면 메모에 없는 날씨를 지어내서, 날씨·병원은 "메모에 적힌 ~"으로 범위를 묶었다.
- **응답 파싱**: JSON 앞에 설명이 붙거나 따옴표가 빠진 JSON도 읽는다. 이모티콘과 ㅋㅋ·ㅠㅠ 같은 자모는 코드로 지운다.
  - "ᄒᄒ", "ᅲ"처럼 모양만 같은 조합용 자모도 지운다. 실험 응답에서 5번 나왔다.
  - 지우기 전에 NFC로 합쳐서, 자모로 쪼개진 글자가 지워지지 않게 한다.
  - 줄바꿈은 공백으로 바꾼다. 말투 예시에 줄바꿈이 있으면 대본도 여러 줄로 나왔다.
- **기본 대본** (API 키가 없거나 호출이 실패할 때): 맺음말을 말투에 맞춘다. 자녀가 하지 않은 약속("또 연락드릴게요")은 넣지 않는다.

## 7. API 변경

| 요청 | 바뀐 점 |
|---|---|
| `POST /api/messages` | 대본 하나 대신 후보 3개를 만든다. 후보가 하나뿐이면 바로 고른 상태 |
| `POST /api/messages/{id}/choose` | 새로 생김. `{"style": "warm"}`으로 후보를 고른다 |
| `POST /api/messages/{id}/rewrite` | 후보 3개를 다시 만든다. `{"speech_level": "존댓말"}`을 주면 그 말투로 |
| `POST /api/messages/{id}/render` | 후보를 고르기 전이면 400 |
| `PUT /api/parent` | `child_call_name`, `speech_level`(`""`/`"반말"`/`"존댓말"`) 추가 |
| `GET /api/watch/{token}` | `child_name`이 부모님 정보의 자녀 이름 |

메시지 응답에 추가된 필드:

- `candidates[]`: `style`, `label`, `script`, `source`, `char_count`, `est_seconds`, `warnings`(사실 경고), `problems`(영상을 막는 문제)
- `chosen_style`, `speech_level`, `script_warnings`

`warnings`와 `problems`는 저장하지 않고 응답할 때마다 계산한다. 그래서 검사 규칙을 바꾸면 예전 메시지에도 바로 적용된다.

## 8. DB 변경

| 테이블 | 추가한 열 |
|---|---|
| `parent_profiles` | `child_call_name`, `speech_level` |
| `messages` | `candidates` (JSON), `chosen_style`, `speech_level`, `script_context` (JSON, 10번) |

서버가 켜질 때 `db._add_missing_columns()`가 기존 SQLite 파일에 없는 열을 추가한다. 개발용 간이 마이그레이션이라 열 이름 변경이나 삭제는 처리하지 않는다. 운영 DB로 옮길 때는 Alembic을 쓴다.

## 9. 화면 변경

- **부모님 정보** (`onboarding/parent`): 말투 선택(예시 문장과 함께), 자녀 이름 입력(필수).
- **새 메시지** (`messages/new`): 생성 중 안내를 "분위기가 다른 대본 3개를 쓰고 있어요…"로 바꿨다.
- **메시지 상세** (`messages/[id]`)
  - 후보를 고르기 전에는 고르는 화면만 보인다. 카드마다 글자 수, 예상 시간, 노란 경고, 빨간 문제가 표시된다.
  - 고른 뒤에는 아래에서 대본을 직접 고칠 수 있다.
  - 고친 내용이나 만들어 둔 미리보기가 사라지는 동작 전에는 확인 창을 띄운다.

## 10. 대화 맥락 반영 (대화방)

대상자별 대화방에서 부모님이 답글을 남기면, 다음 편지 대본이 그 답글에 짧게 반응한다. 예: 답글 "무릎이 좀 쑤시네" → "엄마, 무릎 아파서 어떡해. 다음 주 화요일에 …"

- **넣는 것**
  - 그 대상자에게 가장 최근에 보낸 편지 1통
  - 그 뒤 7일 안에 달린 부모님 답글 중 최근 3개 (각 150자까지)
  - 답글이 없으면 아무것도 넣지 않고, 프롬프트도 예전과 똑같다.
- **이렇게 제한한 이유**
  - 대화 전체를 넣으면 토큰이 늘어 호출 한도와 비용을 빨리 쓴다.
  - 오래된 답글에 뒤늦게 반응하면 어색하다.
- **프롬프트**: 사용자 프롬프트에 '최근 대화'와 대화 규칙을 붙인다.
  - 호칭 다음에 답글에 한 문장으로 반응하고 메모를 전한다.
  - 답글에 없는 내용은 지어내지 않고, 직전 편지 내용은 다시 쓰지 않는다.
  - '담백하게'는 메모만 전하는 분위기라 반응하지 않는다.
- **사실 검사**: 답글에 나온 날씨·요일·시각은 지어낸 것으로 보지 않는다. 메모 내용이 빠졌는지는 계속 메모만 기준으로 본다.
- **저장**: 대본을 만들 때 넣은 맥락을 `messages.script_context`에 남기고 API 응답에도 담는다. 화면 경고도 같은 답글을 기준으로 계산한다.
- **코드**: `routers/messages.py`의 `_conversation_context`가 맥락을 고르고, `script_llm.generate_candidates(..., replies=, previous_script=)`로 넘긴다.

### 대화 맥락 반영 실험 (2026-10-27)

**맥락 고르기 확인**: 테스트용 DB로 13가지 경우를 확인했고 모두 의도대로 나왔다. 확인한 경우는 이렇다.
- 직전 편지보다 먼저 달린 답글, 다른 대상자의 답글, 7일 지난 답글은 빠진다.
- 답글은 최근 3개만 오래된 순으로 들어가고, 150자에서 자른다.
- 초안은 직전 편지로 치지 않는다.

**실제 HyperCLOVA X**: 답글 상황 3개("친구랑 공원에서 산책했어", "비가 와서 집에 있었어 / 무릎이 좀 쑤시네", "목소리 들으니 좋다")로 돌렸다. 맥락 있음은 2번씩, 맥락 없음은 1번씩이다.

| 답글에 반응한 후보 | 담백하게 | 다정하게 | 밝게 |
|---|---|---|---|
| 맥락 없음 | 0/3 | 0/3 | 0/3 |
| 맥락 있음 | 0/6 (의도대로) | 4/6 | 1/6 |

- 경고가 난 후보는 0개였고, 메모 내용도 모두 그대로 전했다. 메시지당 호출 수도 같았다 (3.8번 / 3.7번).
- 백엔드 테스트 60개와 `tsc --noEmit`이 통과했다.

아직 하지 않은 것:

- 브라우저에서 화면을 직접 눌러 보지 않았다.
- 확인에 쓴 스크립트는 저장소에 넣지 않았다.

## 알려진 한계

- **답글 반응이 들쭉날쭉하다**
  - '밝게'는 거의 반응하지 않는다 (1/6).
  - "목소리 들으니 좋다"처럼 정보가 적은 답글에는 잘 반응하지 않는다.
  - "무릎" 답글을 보고 "정형외과"처럼 세부 내용을 짐작해 넣기도 한다.
  - 대화 규칙에 반응 예시를 넣어 보는 것이 다음 단계다.
- **오래된 대화는 기억하지 못한다**: 직전 편지 이후 7일 안의 답글만 넣는다. 오래 이어지는 관심사(건강, 가족 행사)까지 반영하려면 월별 포트폴리오 같은 요약을 '최근 소식'으로 넣는 방법을 검토한다. LLM 요약·사실 검사·외부 도구처럼 단계가 늘어나면 그때 LangGraph도 다시 검토한다.
- **돈이라는 말과 떨어진 요청은 못 잡는다**
  - 예: "병원비가 많이 나와서 놀랐어. 조금만 도와줄 수 있을까?"
  - "도와줄 수 있을까"는 이사·집안일 부탁과 정규식으로 구분할 수 없다.
  - AI는 규칙 8이 있어도 메모의 돈 요청을 대본에 옮긴다 (1차 14번 중 11번). 그래서 표현이 바뀔 때마다 빈틈이 생길 수 있다. 메모와 비교하는 LLM 검사 단계가 생기면 같이 보는 게 좋다.
- **호출 제한(429)에 걸리면 기본 대본이 나온다**
  - 지금 키는 테스트 앱 키라서 HyperCLOVA X 한도가 분당 200회, 30,000토큰이다 (응답 헤더로 확인).
  - 토큰은 입력에 `maxTokens`(300)를 더해서 센다. 첫 호출이 812토큰이고, 다시 쓰기는 앞 대화가 붙어서 더 크다.
  - 분량을 맞추고 `maxTokens`를 낮춘 뒤 메시지 1개가 약 3,450토큰을 차지한다. 모든 사용자를 합쳐 분당 메시지 9개 정도가 한계다 (예전에는 약 6개).
  - 1차 실험은 쉬지 않고 돌렸더니 429가 약 25초 이어졌고, 2초·4초 쉬고 다시 불러도 풀리지 않았다. 그래서 생성의 24%가 기본 대본이 됐다.
  - 2·3차 실험처럼 메시지 사이에 12초씩 쉬면 0번이었다.
  - 근본적으로는 서비스 앱 키가 필요하다. 문서에 나온 HCX-003 서비스 앱 한도는 분당 700회, 150,000토큰이다. 신청과 심사가 필요하고, 요금은 테스트 앱처럼 쓴 토큰만큼 낸다.
- **말투 예시의 '성격'이 반영되지 않는다**: 무뚝뚝한 말투는 22%만 반영됐다. 예시가 있으면 문장 길이와 애정 표현 정도도 예시를 따르게 하거나, 자녀가 직접 고친 대본을 예시로 쓰는 방법을 검토 중이다.
- **기본 대본은 말투가 섞일 수 있다**: 메모를 그대로 붙이기 때문에 메모가 반말이고 말투가 존댓말이면 "엄마, 주말에 갈게. 늘 건강 챙기세요."가 된다.
- **메모에 없는 날짜를 지어낸 경우는 잡지 않는다**: 날짜는 빠짐·바뀜만 본다.
- **띄어 쓴 "한 시"는 여전히 1시로 읽는다**: 예: "딱 한 시기". 실제 메모에는 드물다.
- **애매한 요청은 막지 않는다**: "카톡으로 보낸 거 확인해 줘"는 평범한 말과 구분이 안 된다.
- **자녀가 보내겠다는 돈 얘기도 막힌다**: "용돈 보내 드릴게요", "돈 필요하면 말해"는 막힌다. MVP 때부터의 기준이다. 이미 받은 돈에 대한 인사("용돈 보내줘서 고마워")는 통과한다.
- **시간 한도가 아주 드물게 조금 넘을 수 있다**: httpx timeout은 연결, 읽기 단계마다 따로 적용된다.
- **지어낸 약속·세부 내용은 정규식으로 못 잡는다**
  - "이따 전화할게", "선물이랑" 같은 것은 메모와 비교하는 LLM 사실 검사 단계가 필요하다.
  - 실험 예: 약 복용 메모에 "감기 기운은 좀 어때?"를, 치과 메모에 "안과도 들릴 건데"를 지어냈다.
  - 같은 약 복용 메모에 "오후 4시에 병원 예약"처럼 시각이 붙은 일정을 지어낸 것은 시각 검사로 잡혔다.
