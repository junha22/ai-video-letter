# 대상자별 대화방과 월별 포트폴리오

영상 편지함은 대상자별로 나뉘며, 각 대상자의 영상과 시니어 답글을 날짜별로 이어 보여 줍니다. 사용자는 로그인한 상태에서 영상을 만들고 승인합니다. 시니어는 공유 링크로 들어와 영상을 보고 답글을 남깁니다. 답글 작성 후 사용자가 다시 영상 편지를 보내 같은 대화를 이어갑니다.

## 화면과 이용 순서

1. 기존 온보딩에서 동의, 기본 부모님 정보, 목소리, 얼굴 사진을 등록합니다.
2. `/letters`에서 기본 대상자를 선택하거나 다른 대상자를 추가합니다. 추가 대상자는 전화번호 없이도 등록할 수 있으며 한 계정에 최대 50명까지 등록할 수 있습니다.
3. `/conversations/<recipient_id>`에서 오늘 대화와 지난 날짜를 확인합니다. 대상자 정보 수정과 월별 포트폴리오도 이 화면에서 제공합니다.
4. 영상 작성 화면의 대상자를 확인하고 대본 생성, 영상 생성, 미리보기, 승인을 진행합니다. 대화방의 새 영상 버튼은 선택한 대상자를 작성 화면으로 전달합니다.
5. 승인된 영상의 `/w/<token>` 링크를 공유합니다. 링크를 연 시니어는 로그인 없이 해당 대상자의 대화방을 이용합니다.
6. 시니어가 답글을 보내면 사용자의 대화방과 알림에 반영됩니다. 대화 화면은 주기적으로 다시 조회하고 창에 돌아왔을 때도 갱신합니다.
7. 지난 대화는 대상자별 날짜 목록에서 보고, 월별 포트폴리오는 작성·재작성하거나 텍스트로 내려받습니다.

`/dev-preview`는 별도의 샘플 화면입니다. 실제 대화 저장·공유·분석에는 API와 DB가 필요합니다.

## 날짜와 보관 기준

모든 대화 날짜는 **Asia/Seoul, UTC+9** 기준입니다. 서버는 고정 UTC+9 오프셋을 사용하므로 운영체제의 로컬 시간대와 별도 `tzdata` 설치에 의존하지 않습니다. 저장 시각과 API의 `created_at` 등 시각 필드는 UTC이며 `Z`로 끝납니다.

| 항목 | 소속 날짜·이벤트 시각 |
|---|---|
| 승인된 영상 | `approved_at`, 이전 데이터에 승인 시각이 없으면 `created_at` |
| 작성·생성 중인 영상 | `created_at`; 로그인한 사용자에게만 표시 |
| 시니어 답글 | 서버가 답글을 저장한 `created_at` |

발송 표시나 시청 여부가 바뀌어도 영상의 날짜는 다시 바뀌지 않습니다. 어제 작성한 초안을 오늘 승인하면 오늘 영상으로 표시됩니다. 어제 영상을 보고 오늘 답글을 달면 답글은 오늘 대화에 들어갑니다. 요청 본문으로 답글의 날짜를 지정할 수 없습니다.

00시가 지나면 오늘 조회가 새 날짜로 바뀝니다. 이전 데이터를 별도 테이블로 옮기거나 지우는 배치 작업은 필요하지 않습니다. 날짜별 목록과 선택한 날의 이벤트를 같은 데이터에서 조회합니다. 프론트엔드도 한국 시간으로 날짜를 표시하고 자정·주기적 조회 시 최신 날짜를 반영합니다.

이벤트는 실제 UTC 시각, 이벤트 종류, ID 순으로 정렬합니다. 페이지 커서는 마이크로초를 보존하며, 같은 시각의 여러 이벤트도 중복·누락 없이 이전 페이지를 조회할 수 있습니다. SQLite 날짜 집계는 소수 초의 반올림 때문에 자정 직전 데이터가 다음 날로 넘어가지 않도록 처리합니다.

## 데이터와 기존 기능의 호환성

| 데이터 | 역할 |
|---|---|
| `parent_profiles` | 기존 온보딩의 계정별 기본 연락처. 기존 단일 프로필 관계를 유지 |
| `recipients` | 여러 대화 대상자의 호칭·관계·연락처·말투. 기본 대상자는 `legacy_parent_id`로 기존 프로필과 연결 |
| `messages.recipient_id` | 영상이 속한 대화 대상자 |
| `senior_replies` | 대상자별 답글·서버 저장 시각·참조 영상·재시도 식별자 |
| `monthly_portfolios` | 대상자·월별 보고서, 생성 시각, 원본 답글 지문과 집계 정보 |
| `notifications.recipient_id` | 시청·답글 알림에서 해당 대화방으로 이동하는 대상자 |

API와 워커가 시작될 때 `init_db()`가 새 테이블·필요한 열·인덱스를 추가합니다. 기존 부모님 프로필을 기본 대상자로 복사하고 기존 영상에 해당 대상자를 연결합니다. **기존 사용자·부모님·영상 ID, 공유 토큰, 미디어 경로는 바꾸지 않습니다.** 마이그레이션은 반복 실행할 수 있으며 기존 DB를 삭제하거나 초기화하지 않습니다.

기존 `/api/parent`와 온보딩 화면은 계속 동작합니다. 기본 부모님 정보를 수정하면 기본 대상자를 갱신하고, 기본 대상자를 수정하면 기존 프로필도 갱신합니다. 추가 대상자 수정은 다른 대상자에 영향을 주지 않습니다. `/api/messages`의 `recipient_id`를 생략한 기존 클라이언트는 기본 대상자에게 영상을 만듭니다.

기존 `Message.parent_id`는 호환성을 위해 남습니다. 새 대화방 분리와 영상 대본 작성에는 `recipient_id`와 해당 대상자의 정보·말투를 사용합니다.

## API: 로그인한 사용자

모든 경로는 기존 세션 쿠키 인증과 사용자 소유권 검사를 사용합니다. 다른 계정의 대상자·대화·보고서에는 접근할 수 없습니다.

| 메서드·경로 | 동작 |
|---|---|
| `GET /api/recipients` | 대상자 목록과 전체·오늘 영상/답글 수, 최근 활동 시각·미리보기 |
| `POST /api/recipients` | 대상자 생성, 성공 시 `201` |
| `GET /api/recipients/{id}` | 대상자와 집계 정보 |
| `PUT /api/recipients/{id}` | 대상자 정보 수정 |
| `GET /api/conversations/{id}` | 선택한 날짜의 대화, 날짜별 영상·답글 집계 |
| `GET /api/recipients/{id}/portfolio?month=YYYY-MM` | 해당 월의 현재 답글 집계·저장 보고서·갱신 필요 여부 |
| `POST /api/recipients/{id}/portfolio?month=YYYY-MM` | 해당 월의 전체 답글로 보고서 생성·재작성. 요청 본문 불필요 |
| `POST /api/messages` | 기존 `memo`, `template`과 선택적 `recipient_id`로 영상 편지 작성 |

대상자 생성·수정 본문은 다음 필드를 사용합니다. `nickname`, `relation`은 공백 제거 후 1~20자, `phone`은 생략·빈 문자열 또는 유효한 한국 휴대폰 번호, `child_call_name`은 최대 20자, `speech_level`은 `""`, `"반말"`, `"존댓말"` 중 하나, `tone_examples`는 최대 500자입니다.

```json
{
  "nickname": "엄마",
  "relation": "어머니",
  "phone": "010-1234-5678",
  "child_call_name": "민수",
  "speech_level": "존댓말",
  "tone_examples": "오늘 하루는 어떠셨어요?"
}
```

대상자 응답은 위 정보와 `id`, `child_name`, `is_primary`, `video_count`, `reply_count`, `today_video_count`, `today_reply_count`, `last_activity_at`, `last_preview`를 포함합니다. 사용자 측 영상 수에는 삭제되지 않은 초안도 포함됩니다.

대화 조회 쿼리는 `date=YYYY-MM-DD`이며 생략하면 오늘입니다. `limit`은 기본 100, 범위 1~200입니다. `before`에는 앞선 응답의 `next_before`를 그대로 넘깁니다. 커서는 불투명 문자열이며 클라이언트에서 날짜로 변환하지 않습니다. 응답은 다음 형태입니다.

```text
{
  recipient, child_name, today, selected_date, timezone: "Asia/Seoul",
  days: [{date, video_count, reply_count}],
  events: [
    {type: "video", id, created_at, date, message: {...}},
    {type: "reply", id, created_at, date, text, message_id}
  ],
  has_more, next_before
}
```

영상 이벤트의 `created_at`은 대화 정렬에 쓰는 승인 시각입니다. 내부 `message.created_at`은 원래 영상 작성 시각입니다. 사용자용 `message`에는 기존 영상 생성 상태·편집 정보와 공유 정보, `recipient_id`, 대상자별 공유에 쓸 `recipient` 정보가 포함됩니다. 대화 API는 전체 원문을 불러온 뒤 자르는 대신 선택 날짜와 페이지 크기로 DB 조회를 제한합니다.

잘못된 날짜·월·커서·입력 값은 `422`, 존재하지 않거나 소유하지 않은 대상자는 `404`, 답글이 없는 월의 보고서 생성은 `409`를 반환합니다. 미래 날짜·월은 조회하지 않습니다.

## API: 시니어 공개 대화방

공유 토큰은 **해당 사용자와 대상자의 대화방 전체**를 여는 권한입니다. 최초 공유 영상 한 편에만 제한되지 않으며 이후 승인된 영상도 볼 수 있습니다. 다른 대상자나 다른 사용자의 대화에는 접근할 수 없습니다. 별도 시니어 계정, 로그인, 본인 확인은 없습니다. 링크를 가진 사람이 접근·작성할 수 있으며 작성자를 인증했다는 표시를 하지 않습니다.

| 메서드·경로 | 동작 |
|---|---|
| `GET /api/watch/{token}/conversation` | 공개 대화와 날짜 목록. 사용자 대화와 동일한 날짜·페이지 쿼리 |
| `POST /api/watch/{token}/replies` | 시니어 답글 저장 및 사용자 알림, 성공 시 `200` |
| `GET /api/watch/{token}/messages/{message_id}/video` | 같은 대화방의 승인된 영상 재생 |
| `GET /api/watch/{token}/messages/{message_id}/poster` | 같은 대화방의 승인된 영상 포스터 |
| `POST /api/watch/{token}/messages/{message_id}/viewed` | 실제 재생한 영상의 시청 여부·공유 링크 통계·알림 갱신 |

이전 단일 영상 API인 `GET /api/watch/{token}`, `GET /api/watch/{token}/video`, `GET /api/watch/{token}/poster`, `POST /api/watch/{token}/viewed`도 최초 공유 영상에 대해 유지합니다.

공개 대화에는 `approved`, `sent`, `viewed` 상태 영상과 해당 대상자의 답글만 포함합니다. 초안·실패·생성 중인 영상, 사용자 메모, 전화번호, 공유 링크 통계·다른 토큰, 목소리 정보, 월별 포트폴리오는 제공하지 않습니다. 공개 `recipient`는 `id`, `nickname`, `relation`, `child_name`만 포함합니다. 영상 URL도 현재 토큰으로 접근하는 경로입니다.

공개 대화 응답은 사용자 대화 응답에 다음 필드를 추가합니다.

| 필드 | 의미 |
|---|---|
| `expires_at` | 현재 링크의 만료 시각 |
| `linked_message_id` | 최초 공유받은 영상 ID |
| `linked_date` | 최초 공유받은 영상의 승인 날짜 |

공유 토큰은 기존 `SHARE_LINK_DAYS` 설정을 사용하며 기본 30일입니다. 대화 조회, 답글 작성·재시도, 시청 기록, 영상·포스터 요청마다 토큰 만료·철회를 확인합니다. 철회·만료된 토큰은 `410`, 알 수 없는 토큰 또는 다른 대화방의 영상은 `404`입니다. 공개 메타데이터와 미디어는 `Cache-Control: private, no-store`로 제공하여 이전 응답을 캐시로 재사용하지 않게 합니다.

현재 링크 철회는 기존 `ShareLink.revoked` 상태와 동의 철회 처리로 적용됩니다. 별도의 개별 링크 철회·기간 연장 UI/API는 추가하지 않았습니다. 만료된 링크에서 계속하려면 새로 승인한 영상의 유효 링크를 공유합니다.

### 답글과 재시도

```json
{
  "text": "영상 잘 봤어. 오늘은 친구와 산책하고 왔어.",
  "client_id": "b28f84ed-5740-4e1c-8c63-9cb046e73091",
  "message_id": 42
}
```

`text`는 공백 제거 후 1~1000자입니다. `message_id`는 선택 사항이며 현재 대화방의 승인된 영상만 참조할 수 있습니다. 지난 날짜의 영상을 참조해도 답글 자체는 실제 저장한 오늘 날짜에 속합니다.

`client_id`는 8~80자의 영문·숫자·`_`·`-` 문자열입니다. 클라이언트는 한 번의 전송과 네트워크 재시도에 같은 값을 사용합니다. `(recipient_id, client_id)` 고유 제약으로 동일 전송의 답글과 알림을 한 번만 저장합니다. 같은 식별자로 다른 내용·참조 영상을 보내면 `409`입니다. 저장된 답글을 다시 받는 경우에도 토큰을 다시 검사하므로 만료·철회 이후에는 재시도가 허용되지 않습니다.

대상자 대화방마다 **1분에 10개, 한국 시간 하루에 120개**까지 답글을 받습니다. 초과 시 `429`와 `Retry-After: 60`을 반환합니다. 이미 저장된 동일 요청의 정상 재시도는 이 개수 제한으로 막지 않습니다. 답글 알림의 종류는 `senior_reply`이며 `recipient_id`로 해당 대화방에 이동합니다.

## 월별 포트폴리오

월 범위도 한국 시간의 월초 00시부터 다음 달 월초 00시 직전까지입니다. 특정 대상자가 해당 월에 남긴 **모든 답글**을 누적해 분석하고, 화면에 현재 표시된 날짜·페이지만 분석하지 않습니다. 보고서는 대상자와 월의 조합마다 한 개를 저장하고 재작성 시 갱신합니다.

응답은 `recipient_id`, `month`, `available_months`, 현재 `reply_count`, `active_days`, `stale`, `portfolio`를 포함합니다. 저장된 보고서가 없으면 `portfolio`는 `null`입니다. 저장 후 답글 내용이나 개수가 바뀌면 원본 지문 비교로 `stale`이 `true`가 되며 화면에서 재작성할 수 있습니다.

`portfolio`의 주요 필드는 다음과 같습니다.

| 필드 | 내용 |
|---|---|
| `id`, `generated_at`, `source` | 저장 ID, 생성 시각, 분석 방식 `local_evidence_v1` |
| `title`, `summary` | 대상자·월 제목과 기록의 범위를 설명하는 요약 |
| `reply_count`, `active_days`, `days_in_month` | 답글 수, 답글을 남긴 날짜 수, 해당 월의 전체 일수 |
| `topics` | 주제별 답글 수와 근거 `evidence` |
| `daily_trends` | 실제 답글이 있는 날짜별 답글 수·글자 수·확인된 주제 |
| `representative_replies` | 대표 답글의 원문 근거 |
| `conversation_starters` | 확인된 주제를 이어갈 대화 제안 |
| `caveats` | 기록과 분석의 한계 |

원문 근거의 형태는 `{reply_id, text, date}`입니다. 주제는 식사·가족·일상·몸 상태와 휴식·날씨·고마움 등에 해당하는 한국어 키워드가 답글에 포함됐는지로 집계합니다. 한 답글이 여러 주제에 포함될 수 있습니다. 이는 정해진 규칙으로 실제 답글을 정리하는 기능이며 LLM을 호출하지 않습니다. 영상 대본 생성용 `NAVER_API_KEY` 설정과도 별개입니다.

이 분석은 문맥·부정 표현·말투를 완전히 이해하지 못하며, 건강·감정·인지 상태에 대한 진단·점수·추정을 제공하지 않습니다. 답글이 없는 날의 상태를 해석하거나 답글 작성자의 신원을 확정하지 않습니다. 답글이 적을 때와 현재 월의 부분 기록이라는 한계도 보고서에 표시합니다.

### 자동 작성과 운영

현재 월은 사용자가 `POST .../portfolio?month=YYYY-MM`으로 작성·갱신합니다. 완료된 지난 월은 기존 `python -m app.worker` 워커가 자동으로 작성합니다.

- 워커는 작업 큐를 가져오기 전에 약 60초 간격으로 지난 월의 미작성·추가 답글이 있는 보고서를 확인합니다.
- 한 차례에 최대 25개의 변경된 대상자·월을 작성합니다. 밀린 보고서는 다음 확인에서 이어서 처리합니다.
- 워커 재시작 후에도 과거 미작성 월을 찾아 처리합니다. 이미 최신인 보고서는 다시 작성하지 않습니다.
- 워커가 실행되어야 자동 작성됩니다. API만 실행하면 수동 생성·조회는 가능하지만 자동 생성은 진행되지 않습니다.
- 영상 생성이나 음색 학습 같은 긴 GPU 작업을 실행 중이면 해당 작업이 끝나고 워커 루프로 돌아온 뒤 확인합니다. 월초 정각 실행을 보장하는 별도 스케줄러는 아닙니다.
- 자동 보고서 작성 실패는 로그에 남기고 다음 주기에 재시도합니다. 해당 오류가 영상 작업 큐 처리를 막지 않습니다.

## 동의 철회와 동시 요청

기존 동의 철회 경로 `POST /api/consent/withdraw`는 녹음·사진·영상 미디어 삭제와 링크 차단에 더해 해당 사용자의 시니어 답글, 월별 보고서, 답글 내용을 포함한 `senior_reply` 알림을 삭제합니다. 다른 계정의 데이터는 영향을 받지 않습니다. 대상자 연락처와 기존 대본 생성 로그는 유지하고, 삭제 기록에는 처리 건수를 남깁니다.

답글 저장·보고서 생성·시청 상태 변경은 동의 철회와 저장 순서를 조율합니다. PostgreSQL은 사용자 행 잠금, SQLite는 사용자 행의 무해한 쓰기로 트랜잭션 쓰기 잠금을 사용합니다. 공개 쓰기는 잠금을 얻은 뒤 토큰을 다시 검사합니다. 철회 직전에 진행 중이던 요청 때문에 답글·보고서가 다시 남거나 삭제된 영상 상태가 시청 상태로 되돌아가지 않도록 검증했습니다.

## 검증

백엔드 의존성이 설치된 Python 환경에서 프로젝트 루트에서 실행합니다.

```powershell
python -m unittest discover -s backend/tests -v
python -m compileall -q backend/app
```

`backend/tests/test_conversations.py`의 통합 테스트 23개는 다음 범위를 포함합니다.

- 실제 과거 SQLite 스키마에서 새 열·테이블 추가, 반복 이관, 기존 ID·공유 토큰 보존
- 여러 대상자 생성·수정과 기본 프로필 동기화, 선택한 대상자의 대본 생성·승인
- 다른 사용자·다른 대상자의 대화·영상·보고서 접근 차단, 미승인 영상·개인정보 비공개
- 공개 링크 만료·철회·삭제, 영상·포스터 요청 재검사, 실제 재생한 영상의 시청 통계
- 답글 검증·참조 영상 범위·속도 제한·중복 재시도·동시 전송·알림 한 번 저장
- KST 자정·월초, 자정 직전 마이크로초, 실제 시각 순서와 페이지네이션
- 월별 전체 답글의 근거 분석·갱신 필요 감지·지난달 자동 작성과 반복 실행
- 동의 철회와 답글 저장·보고서 생성·시청 상태 변경이 겹치는 경쟁 조건

테스트는 앱을 불러오기 전에 `DATABASE_URL`, `DATA_DIR`, 세션 시크릿과 제공자 설정을 테스트용 값으로 바꿉니다. 별도 SQLite DB·임시 미디어 디렉터리·고정 시계를 사용하고 종료 시 정리합니다. 실제 `backend/data`, 기존 사용자 데이터, GPU 작업, 외부 LLM·TTS·영상 서비스에는 접근하지 않습니다.

프론트엔드 검사는 프로젝트 루트에서 실행합니다.

```powershell
npx.cmd --no-install tsc --noEmit
npm.cmd run lint
npm.cmd run build
```

실제 시니어 휴대폰에서 공유하려면 기존 `PUBLIC_BASE_URL`을 휴대폰에서 접근 가능한 배포·터널 주소로 설정해야 합니다. `localhost` 링크는 다른 기기에서 열리지 않습니다.
